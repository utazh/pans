## 二、DeepSeek-V4.1 到底怎么做到大范围共享？

官方配置中，40 层模型的全局 KV 来源层只有：

```text
2、8、14、20
```

而索引来源层是：

```text
2、8、14、20、24、28、32、36
```

所以它确实把“共享记忆”和“重新决定读哪些位置”分开了。配置同时保留了 128-token 的滑动窗口。:chatgpt-content-reference{index="5"}

报告中的三种模式为：

| 模式 | 全局 KV | Top-K 位置 |
|---|---|---|
| Full | 本层产生 | 本层选择 |
| Reindex | 复用来源层 | 本层重新选择 |
| Reuse | 复用来源层 | 复用已有选择 |

**三种模式都保留本层 Q 和本层 SWA KV，而且这个共享结构参与了模型训练。**因此，它不是把普通模型的所有历史信息直接替换成别层 KV。:chatgpt-content-reference{index="6"}

### 对我们最重要的启发

不是机械复制“40 层只有四份全局 KV”，而是学习：

> **大规模历史记忆可以共享，但少量层专属记忆不必强行共享。**

还需要划清边界：DeepSeek 的 SWA Bounded Replay 是近似重算短窗口的机制，不能直接搬到你的 dense Qwen。**我们的 prefix 已经命中并保存在 SSD，下一版仍然直接拉取 KV，不重新计算旧 prefix。**:chatgpt-content-reference{index="7"}

此外，你原系统已经通过 prefix 命中避免了完整 prefix 重算。我们应计算的是**少恢复、少组织、少保存 KV 的增量收益**，不能把原本就避免的 prefill 计算再算成跨层共享的贡献。

## 三、下一轮主方案：扩大共享，同时允许一个很小的本层原生 prefix 区域

### 1. 先保留纯共享路线，不把新组件强加给全部实验

下一轮首先比较：

| 结构 | 含义 |
|---|---|
| **R=0：纯共享** | consumer 的整个已选 prefix 都使用 source KV |
| **R=4：少量原生保留** | consumer 的已选 prefix 中，最后 4 个物理块用自己的原生 KV，其余共享 |

两者使用相同的来源图、初始化、训练数据和训练配置。**R=4 是一个预先指定的小范围验证，不是已经找到的最佳值。**

即使 R=4 没有改善，也应保留 R=0 的 G24/G22 扩层实验，不能再次因为一个新组件失败，就回到“只允许研究三层”。

### 2. 为什么增加这点原生 prefix？

当前 reader 必须用 source 的信息模拟目标层的全部已选 prefix。线性变换能改变坐标、尺度和组合方式，**但不能恢复 source 表示中完全没有的信息**。

因此，我提出一个需要实验验证的假设：

> **把一小部分靠近已选前缀末端的历史信息保留为本层原生 KV，可能减少 reader 必须承担的误差，使更多层能够共享其余大部分记忆。**

这是受 DeepSeek“共享全局记忆＋本层局部记忆”分工启发的设计，**不是已经证明 Qwen 的主要误差恰好来自这几个块**。

### 3. 必须保持 25% 预算不变

这里不是把“最近 64 个 token”额外加入原来的稀疏注意力。

假设当前层原来的选择集合为 \(\mathcal I_\ell\)，新方案只把它分成两部分：

\[
\mathcal I_\ell=\mathcal C_\ell\;\dot\cup\;\mathcal R_\ell
\]

其中：

- \(\mathcal C_\ell\)：仍从 source 读取的部分；
- \(\mathcal R_\ell\)：原选择集合中最后 \(r\) 个完整物理块，读取本层原生 KV。

**不增加 token、不删除 token、不改变精度、不改变 P8。**

“最后 4 个已选块”也不一定是连续的最后 64 个绝对位置 token，所以它**不是 SWA 的等价实现**。选择这个形式，是为了与现有连续块加载兼容，并且避免重排或重建长 prefix。

## 四、运行时怎样计算？仍然是你的 Q／输出变换

对 consumer 层 \(\ell\)，共享部分计算：

\[
S_C=
\frac{(Q_\ell A_\ell^\top)K_a[\mathcal C]^\top}{\sqrt d}
+
\frac{Q_\ell(b_\ell^K)^\top}{\sqrt d}
\]

本层保留的 prefix 与当前 query／生成 token 的私有 KV 合为另一条分支：

\[
S_N=
\frac{
Q_\ell
[K_\ell[\mathcal R];K_\ell^{\rm private}]^\top
}{\sqrt d}
+\text{causal mask}
\]

两部分**共同归一化**后：

\[
O_\ell
=
(P_CV_a[\mathcal C])B_\ell
+
\beta_C b_\ell^V
+
P_NV_\ell^{[\mathcal R;\rm private]}
\]

其中 \(\beta_C\) 是分配给共享部分的总注意力质量。

这意味着：

**共享部分：**继续用当前层的 Q 变换和输出变换。

**少量原生部分：**不做这些补偿，直接使用当前层本来的 K/V。

**当前 query／生成 token：**仍然逐层独立保存，不与历史 prefix 混成一个跨层缓存。

### 关键工程约束

source 的完整已选 KV 仍然只恢复一次。consumer 的共享部分直接使用它的前段视图，**不生成 consumer 专属的大型 KV 张量**。

少量本层原生块与 private tail 拼接，所以每个共享 consumer 仍然是两次 attention，而不是新增第三次 attention。但原生块的加载、拼接、评分维护都有成本，**不是零开销**。

特别是缓存晋升只能更新这些原生块。新代码不会把 consumer 的整个逻辑选择集合重新晋升，否则会把想省掉的数据又全部读回来。

## 五、这还能算大范围共享吗？能，但要换成诚实的资源口径

引入原生块后，\(G\) 应定义为：

> **保存完整已选 prefix 的主来源数量。**

它不再等于“所有读取过的层数据对象数”，因为 consumer 还有小块原生 KV。

忽略不同层预算差异时，payload 比例约为：

\[
\boxed{
\frac{G}{L}
+
\left(1-\frac{G}{L}\right)\frac{r}{m}
}
\]

其中 \(m\) 是每层已选块数，\(r\) 是 consumer 保留的原生块数。

例如仅作算术说明：

\[
L=28,\quad G=14,\quad m\approx77,\quad r=4
\]

则 payload 大约保留 52.6%，减少 47.4%。**这不是实测压缩率，也没有扣除 reader、packed 副本及工作区。**

所以，真正要研究的是：

> **付出很少的层专属数据，能否让一半甚至更多的完整 prefix KV 副本不再需要恢复？**

如果质量没有改善，或者小块请求和缓存管理抵消了收益，这条分支就不成立。新实验必须允许得到这个负结果。

## 七、你问“是不是离线判断、是不是训练”：这里需要明确回答

**是的，当前方案包含离线决定和离线训练；它不是 training-free。**

| 阶段 | 做什么 | 是否在线 |
|---|---|---|
| prefix 准备 | 计算并保存已有 prefix KV | 离线／首次构建 |
| 共享结构设计 | 确定哪些层读哪个 source、原生保留预算 | 离线 |
| reader 校准 | 用 teacher 记录更新 A/B/bK/bV | **离线训练** |
| 请求到来 | P8 根据当前 query 选择 blocks | 在线 |
| 数据恢复 | 拉取 source KV 和必要原生块 | 在线 |
| 读取 | 当前 Q 变换、attention、输出变换 | 在线 |

报告已经明确：主干冻结，只训练 A/B/bK/bV，当前 query 和生成 token 的 KV 由 student 逐层重算。:chatgpt-content-reference{index="10"}

所以，更准确的称呼是：

> **冻结主干、离线 reader 蒸馏、在线物理 prefix KV 复用。**

不是“没有训练”，也不是“每个请求临时训练”。

正式请求中不计算 teacher、不读取正确标签、不检查原模型答案。请求只使用预先生成的结构和 reader。

### 目前 reader 也不是通用的跨模型插件

你当前的矩阵绑定：

\[
\text{模型权重}
+\text{prefix}
+\text{位置配置}
+\text{保留预算}
+\text{校准分布}
\]

更换 prefix 后，当前前缀特定 reader 通常也需要重建或重新校准。**“任意 prefix 使用同一套 reader”还不是现有实验已经证明的能力。**

离线成本应当报告，并给出复用次数的摊销：

\[
\text{复用次数}\times\text{单请求节省}
>
\text{新增离线构建成本}
\]

一次性 prefix 不一定适合这套方案；重复命中的长 prefix 才更符合目前设计。

## 八、换 Qwen2.5-14B，需要重新适配吗？

**算法不局限于 7B，但参数和资源一定不能直接沿用；实现需要按新几何配置，并重新做数值验收。**

| 几何 | Qwen2.5-7B | Qwen2.5-14B |
|---|---:|---:|
| 层数 | 28 | 48 |
| Q heads | 28 | 40 |
| KV heads | 4 | 8 |
| head dimension | 128 | 128 |
| 每 KV 组对应的 Q heads | 7 | 5 |

7B 几何已由你的实验确认，14B 数值来自官方配置。:chatgpt-content-reference{index="11"}:chatgpt-content-reference{index="12"}

因此，14B 需要重新准备：

**prefix store、物理 Pcache、8-head K4 索引、teacher 记录、来源图和 reader。**

原来代表 Q heads 为 `0,7,14,21`，14B 对应可按 GQA 组推导为：

```text
0,5,10,15,20,25,30,35
```

新代码提供配置检查和自动推导，不再把这一组数字固定为 7B。

### 但显存是现实限制

官方模型卡列出 14B 模型约 **14.7B 参数**。按 BF16 估算，仅权重就约 29.4 GB，约 27.4 GiB，尚未计入 KV、激活和 reader，因此单张 24 GiB 显卡装不下完整 BF16 路径。:chatgpt-content-reference{index="13"}

当前代码仍是单 GPU 实现，没有完成 tensor parallel 或 `device_map` 分片。

**建议先在容量足够的单 GPU 上验证 14B。**不能只加 `device_map="auto"` 就声称多卡共享缓存、跨层 source 和反向图都已适配；使用权重量化也需要新的数值与性能控制。

所以答案是：

> **Qwen2.5-14B 大概率可沿用同一种算法和主要代码结构，但必须重建模型专属资源、重新训练 reader，并通过真实模型测试；目前不是已经完成 14B 适配。**

其他架构若有 QK norm、不同 RoPE、滑动窗口、MLA 或不同 cache API，还需要单独修改。

## 九、“这算 trick 吗？”以及哪些能作为创新

**模型专属的离线校准本身不是 trick。**量化、剪枝、低秩压缩和蒸馏也常有模型专属参数。问题在于：是否清楚说明使用了什么数据、适用什么范围，并在公平条件下证明新增机制的价值。

当前比较容易被质疑的地方不是“做了训练”，而是：

> **只有一个模型、一个固定 prefix、一个任务候选空间，并且共享比例仍小。**

这些限制需要通过实验扩展，而不是通过命名解决。

### 我会这样划分你的贡献

| 内容 | 我的判断 |
|---|---|
| 冻结主干，通过 Q／输出读侧适配实现实际跨层 prefix KV 共享 | **核心候选贡献**，但要与已有跨层共享、分解方法比较 |
| 面向 prefix-hit reprefill，避免消费者 KV 重建，按物理对象去重恢复 | **最贴合场景的系统贡献候选** |
| 大范围共享＋有界的本层原生 prefix 保留 | **本轮待验证的新结构**，不能先称有效创新 |
| 完整评分／组级 reader 联合校准 | 支撑方法的重要部分，但“蒸馏”本身不是新技术 |
| P8、INT4 selector、普通预取、通用缓存优化 | 作为基础模块或工程优化，不宜分别宣称主要创新 |
| 冷缓存认证、数据隔离、数值回放检查 | 重要的可信实验基础，但不是主要算法创新 |

必须面对已有工作：

- **CLA** 已研究跨层共享，并从共享架构训练模型。
- **KVSharer** 已研究后处理式层间共享。
- **xKV** 已研究跨层共同子空间和选择性重建。
- **MiniCache** 已包含保留不同状态的机制，因此“共享之外留一点原生数据”本身也不是空白。:chatgpt-content-reference{index="14"}

因此，较准确的论文主张应该是：

> **针对已有 prefix 命中的 reprefill，设计冻结主干的读侧跨层复用，使大部分历史记忆由少量物理来源提供，并通过校准与少量原生保留控制误差，将表示共享转化为实际缓存恢复收益。**

这句话里的“大部分”“控制误差”“恢复收益”，都需要下一轮结果来支撑。**目前已有的是小范围物理共享与冷恢复收益；大范围质量保持仍然是研究目标。**

纯共享控制只改 `--native-blocks 0` 和输出目录，保持同一初值。

**原 v24 的 teacher 身份、fit/val 角色检查和原生数值回放门限继续保留。**新包不通过降低门限获得可运行结果。

## 白话版

**下一步确实应该扩大，不应该一直围着最后三层转。**

DeepSeek 的做法也不是“所有层什么都不留，只读别人的 KV”。它让很多层共用大部分历史记忆，同时每层保留一点自己的局部记忆。

所以新一轮做两组：一组直接扩大纯共享；另一组也扩大共享，但给每个消费者留很少一点自己的历史 KV。**两组都还是前缀命中后从 SSD 拉取，不重算 prefix。**

这套方法确实要训练，但训练的是小读取器，不是整个 Qwen。换 14B 后，同样的办法可以继续研究，不过缓存、索引和读取器要按 14B 重做，7B 的矩阵不能直接搬过去。

**我们真正要证明的，不是“最后三层更像原模型”，而是“很多层可以少存、少搬大部分 KV，整体质量仍然保持，并且在真实 reprefill 冷恢复中更快”。这次代码和实验表就是围绕这个目标设计的。**
