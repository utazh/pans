# 投稿前的有限证据计划

## 结论

开始写，但不是只剩美化。v2.6的15/16质量下降是实质结果，不能用TREC25%抵消。创新候选足以开展系统论文，是否达到某个CCF B会议录用标准不能凭点数或单张性能表保证。
论文暂定位“prefix-hit reprefill的质量—恢复成本折中”，不写无损或普遍质量保持。

## 核心叙事

旧prefix被复用时，多个逻辑层拥有各自的读法，但并不必然需要恢复各自全部历史记忆。
层差异转移到短Q/attention输出的小矩阵；物理prefix按source去重；必要时保留有界原生区域。
用户的场景不是初次prefill，也不是只优化decode。已有prefix的所有层KV可用，低层读深层历史source不引入当前token循环依赖。

## 贡献分级

A. 核心候选：冻结主干的读侧跨层共享与reprefill场景结合；不创建完整consumer KV。
B. 系统贡献：shared source/native patch/private tail分离；同support、联合归一化、真实恢复/准入去重。
C. 实验证据：在真实冷恢复中减少host恢复与等待；不是全由H2D带宽决定。
D. R4：当前可选设计与经验结果，不再写真实native信息不可替代。
普通P8、K4、预取、元数据缓存、全局蒸馏、矩阵移项本身、冷认证本身不分别当原创核心。

## 必做、可选与暂缓

必做：
1. 基线身份与effective CLI确认；完整ContiguousKV与P8 identity分列。
2. 冻结R4 / source-proxy / frozen-R0，同图同参数，先同计划后在线；只质量不重选主seed。
3. 25/50%、四任务、G16/20/24/28的相邻受限图；不可行点标记而不暗中放松。
4. 外部KVSharer搜索基线及xKV表示基线；先质量后同系统性能移植。
5. 在development选择少数操作点，冻结，再进行新的不同query blocks配对计时和未见质量检验。

可选：同协议增加校准长度覆盖/相同从头初值的TREC对照；第二模型和一个自由生成任务（要主张通用推理时必做）。
暂缓：新的head routing、动态R、融合kernel、G8极限共享、再换loss、再优化已审计冷流程。

## 对当前数据可直接写的摘要句子

在Qwen2.5-7B四项分类工作负载的16个任务-预算组合上，该实现降低了观察到的SSD冷恢复TTFT 17.87%–42.01%，同时15个组合出现准确率下降。TREC25%的八块主研究显示同晋升条件下冷TTFT降低39.15%，但这一特例不能代表跨任务质量保持。
