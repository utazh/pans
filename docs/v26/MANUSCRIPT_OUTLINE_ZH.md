# 论文起草提纲（不是投稿承诺）

暂定题目：
**Read-Side Cross-Layer Prefix Sharing for Cache-Hit Re-Prefill**
中文：**面向前缀命中重预填充的读侧跨层KV共享**。

## 1. 主张范围

主干冻结；针对会重复命中的已有prefix，离线校准层专属读取器。在线使用P8选择，将大量历史prefix由少数物理source提供，同时保留原已选集合内的少量本层KV。新query与生成token仍逐层独立，所有decoder层都执行。

不要在标题/摘要使用lossless、training-free、all workloads、首次cross-layer等未支持词语。

## 2. 三个贡献段的可写版本

**读侧共享机制。**把层专属差异放到Q和聚合输出侧，直接读取共享prefix实体，而不在每个consumer物化大型专属KV。突出reprefill已有前缀全层KV已知，来源可位于consumer后层；不是在线当前token循环依赖。

**有界本层例外。**在保持原稀疏选择集合和预算不变时，保留少量本层原生KV；两分支共同归一化，只对共享分支适配。R4与R0同图/初始化/种子的对照支撑这一设计，但不声称最后4块位置最优。

**恢复路径实现与评估。**按物理source一次恢复、按原生patch小额准入、独立private cache；把压缩落实到真实文件访问、host恢复、硬件拷贝与首logits延迟。严谨冷热协议是实验贡献组成，而不是新的硬件能力。

以上是贡献候选，需要与CLA、KVSharer、MiniCache、xKV、ReCalKV/MLA明确区分，不是所有组成技巧各自全新。

## 3. 建议章节

1. 场景与动机：prefix-hit re-prefill，TTFT边界；磁盘恢复为何与GPU算术不同。
2. 表示与读取：仿射K/V近似，Q侧吸收，B只作用于共享输出，key bias影响prefix质量。
3. 原生例外与共享图：R是last selected blocks，G不是总恢复次数，token支持不变。
4. 离线训练与在线实现：任务候选蒸馏、数据角色与身份绑定；FP16 payload/BF16计算；P8逻辑选择与物理owner分离。
5. 实验：覆盖率曲线、R消融、近邻强基线、跨prefix/任务、正式配对计时、硬件I/O、摊销。
6. 限制：一模型/一任务现状、非劣未过、自由生成未测、离线成本、新prefix校准、SSD文件未删除。

## 4. 已有数据可写的结果段

在本次Qwen2.5-7B/TREC固定prefix和25%预算下，G16/R4将所选prefix缓存数据减少40.63%，计入reader/packed后该局部缓冲占用减少33.88%。三个训练种子在独立1536题上的准确率分别为74.22%、73.05%、74.48%，无共享为73.24%；预定的三种子非劣要求未通过。在四个顺序平衡计时块中，SSD冷恢复native/preserve平均TTFT分别下降30.70%/36.35%；这些块重复有限query，不代表任意服务负载。所有数字引用原v25报告，并保留统计边界。

不能把这段直接改成“无损压缩、普遍36%加速”。

## 5. 最小补充实验表

| 证据缺口 | 必要对照 | 暂不做 |
|---|---|---|
| reader/原生例外价值 | direct同图、R0/R4、固定R4 source-proxy | 再搜索大规模新矩阵结构 |
| 恢复系统过弱 | 原准入 vs prefetch准入复用，同时用于I/S | 只给共享路径优化 |
| 前缀特异性 | 两个新任务、每个至少两个独立prefix | 继续消耗同一TREC最终集作新选择 |
| 近邻差异 | 至少落实KVSharer或MiniCache/xKV之一 | 仅与不压缩基线比较 |
| 时间普适性 | 不同query block，多个日期/过程记录，同质量资源 | 只重复最有利16题 |
| 模型范围 | 容量允许时第二模型/规模 | 在24GiB卡上声称14B BF16已支持 |
